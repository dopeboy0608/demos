# Feature Specification: 폴리곤 제어 데모 화면 이식

**Feature Branch**: `feature/1-polygon-control`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: "이슈 #1: [Feature] 폴리곤 제어 데모 화면 이식 (지도 2개 + 그리기/합치기/분할/선택) — 이전 회사 데모 화면(DeliveryRegionSettingTestManageBoard.jsx)을 참고해 현재 demos 프로젝트 스펙으로 새로 구현. 지도 2개 렌더링(카카오맵 SDK), 폴리곤 그리기, 합치기 연산(union/intersection/xor/difference), 분할, 선택 기능 포함. 원본 코드는 참고만 하고 그대로 가져오지 않는다."

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 폴리곤 그리기 (Priority: P1)

사용자는 지도 위에서 버튼으로 그리기 모드를 켜고, 클릭으로 꼭짓점을 찍어 하나의 폴리곤(구역)을 완성할 수 있다.

**Why this priority**: 이후의 선택/합치기/분할 기능이 모두 "그려진 폴리곤"을 전제로 하므로, 이 기능 하나만 있어도
"지도 위에 구역을 정의한다"는 데모의 핵심 가치가 성립하는 MVP다.

**Independent Test**: 빈 지도에서 그리기 버튼을 누르고 3개 이상의 점을 클릭한 뒤 완료 동작(더블클릭 등)을 하면,
지도 위에 해당 다각형이 표시되는지로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 폴리곤이 하나도 없는 지도, **When** 사용자가 그리기 모드를 켜고 3개 이상의 점을 찍은 뒤 완료하면, **Then** 찍은 점들을 꼭짓점으로 하는 폴리곤이 지도 위에 표시된다.
2. **Given** 그리기 모드가 켜진 상태, **When** 사용자가 점을 2개까지만 찍고 완료를 시도하면, **Then** 폴리곤이 생성되지 않고 추가 입력을 요구한다.

---

### User Story 2 - 폴리곤 선택 (Priority: P2)

사용자는 지도 위에 그려진 폴리곤 중 하나 이상을 클릭해 선택 상태로 표시할 수 있다.

**Why this priority**: 합치기·분할 연산은 모두 "선택된 폴리곤"을 대상으로 동작하므로, 그리기(P1) 다음으로
필요한 기반 기능이다.

**Independent Test**: 폴리곤이 2개 이상 그려진 상태에서 하나를 클릭하면 해당 폴리곤만 선택 스타일로
바뀌는지로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 폴리곤이 2개 이상 그려진 지도, **When** 사용자가 폴리곤 하나를 클릭하면, **Then** 해당 폴리곤이 선택된 상태로 시각적으로 구분된다.
2. **Given** 폴리곤이 선택된 상태, **When** 사용자가 같은 폴리곤을 다시 클릭하면, **Then** 선택이 해제된다.

---

### User Story 3 - 폴리곤 합치기 연산 (Priority: P2)

사용자는 선택된 폴리곤 2개에 대해 union / intersection / xor / difference 중 하나의 연산을 실행해
새로운 폴리곤을 만들 수 있다.

**Why this priority**: 원본 데모 화면의 핵심 기능이며, 그리기·선택 기능이 갖춰진 뒤 바로 이어지는 다음
가치 단위다. 4개 연산은 버튼만 다를 뿐 동일한 흐름(선택 → 연산 실행 → 결과 반영)이라 하나의 스토리로
묶는다.

**Independent Test**: 폴리곤 2개를 선택한 뒤 연산 버튼(예: union) 하나를 누르면, 두 폴리곤이 사라지고
연산 결과에 해당하는 새 폴리곤 하나가 나타나는지로 각 연산별로 독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 서로 겹치는 폴리곤 2개가 선택된 상태, **When** 사용자가 "union" 버튼을 누르면, **Then** 두 폴리곤을 합친 영역의 새 폴리곤이 지도에 표시되고 기존 2개는 사라진다.
2. **Given** 서로 겹치는 폴리곤 2개가 선택된 상태, **When** 사용자가 "intersection" 버튼을 누르면, **Then** 두 폴리곤이 겹치는 영역만 남은 새 폴리곤이 표시된다.
3. **Given** 폴리곤을 1개만 선택한 상태, **When** 사용자가 합치기 연산 버튼을 누르면, **Then** 연산이 실행되지 않고 "2개 이상 선택이 필요하다"는 안내가 표시된다.

---

### User Story 4 - 폴리곤 분할 (Priority: P3)

사용자는 하나의 폴리곤을 선으로 가로질러 두 개의 폴리곤으로 나눌 수 있다.

**Why this priority**: 합치기의 역방향 시나리오로, 데모의 기능 범위를 완성하지만 핵심 가치(구역 정의·조합)
에는 합치기보다 덜 필수적이다.

**Independent Test**: 폴리곤 하나를 선택하고 분할 도구로 폴리곤을 가로지르는 선을 그으면, 원래 폴리곤이
사라지고 선을 기준으로 나뉜 폴리곤 2개가 나타나는지로 독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 폴리곤 1개가 선택된 상태, **When** 사용자가 분할선을 그 폴리곤을 가로지르게 그리면, **Then** 원래 폴리곤이 사라지고 분할선 양쪽의 폴리곤 2개가 새로 표시된다.
2. **Given** 폴리곤 1개가 선택된 상태, **When** 사용자가 폴리곤을 가로지르지 않는 선을 그리면, **Then** 분할이 실행되지 않고 오류가 안내된다.

---

### Edge Cases

- 그리기 중간에 모드를 취소하면 어떻게 되는가? → 그리던 점들은 모두 버려지고 폴리곤이 생성되지 않는다.
- 합치기 연산 결과가 빈 영역(예: 서로 겹치지 않는 폴리곤의 intersection)이면 어떻게 되는가? → 결과 폴리곤이
  생성되지 않고 "겹치는 영역이 없다"는 안내가 표시된다.
- 폴리곤을 3개 이상 선택한 상태에서 합치기 버튼을 누르면 어떻게 되는가? → union/xor는 전체 폴리곤에 순차
  적용, intersection/difference는 2개 초과 선택을 허용하지 않고 안내를 표시한다(2개 전용 연산으로 간주).
- 지도에 폴리곤이 하나도 없는 상태에서 선택/합치기/분할 버튼을 누르면 어떻게 되는가? → 버튼이 비활성화
  상태이거나, 눌러도 아무 동작이 일어나지 않고 안내만 표시된다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 시스템은 지도 2개를 화면에 동시에 렌더링해야 한다.
- **FR-002**: 사용자는 각 지도에서 그리기 모드를 켜고, 클릭으로 폴리곤의 꼭짓점을 순서대로 추가할 수 있어야 한다.
- **FR-003**: 사용자는 꼭짓점을 3개 이상 찍은 뒤 완료 동작으로 폴리곤 그리기를 확정할 수 있어야 한다.
- **FR-004**: 시스템은 완성된 폴리곤들의 목록을 유지하고 해당 지도 위에 계속 표시해야 한다.
- **FR-005**: 사용자는 지도 위의 폴리곤을 클릭해 선택 상태를 켜고 끌 수 있어야 한다.
- **FR-006**: 사용자는 정확히 2개의 폴리곤이 선택된 상태에서 union / intersection / xor / difference 중
  하나의 연산을 실행할 수 있어야 한다.
- **FR-007**: 시스템은 합치기 연산 실행 시, 연산 결과를 새로운 폴리곤 하나로 지도에 반영하고 연산에 사용된
  원본 폴리곤 2개는 제거해야 한다.
- **FR-008**: 사용자는 선택된 폴리곤 1개를 가로지르는 분할선을 그려 해당 폴리곤을 2개로 나눌 수 있어야 한다.
- **FR-009**: 시스템은 폴리곤이 0개이거나 선택 조건을 만족하지 않을 때 관련 연산 버튼을 비활성화하거나
  실행 시 안내 메시지를 표시해야 한다.
- **FR-010**: 사용자는 지도 위의 폴리곤 하나 또는 전체를 삭제(초기화)할 수 있어야 한다.
- **FR-011**: 시스템은 카카오맵 API 키(`PUBLIC_KAKAO_MAP_API_KEY`)가 설정되지 않았을 때 지도 대신 안내
  메시지를 표시해야 한다.

### Key Entities

- **Polygon(폴리곤)**: 꼭짓점 좌표 목록, 선택 여부, 소속 지도(패널), 생성 방식(직접 그리기 / 합치기 결과 /
  분할 결과)을 가지는 도형. 합치기·분할 연산의 입력이자 결과물이다.
- **Map Panel(지도 패널)**: 지도 인스턴스 하나와 그 위에 속한 폴리곤 목록, 현재 그리기/선택 상태를 가지는
  작업 단위. 화면에는 이 패널이 2개 존재한다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 사용자는 지도 위에서 클릭만으로 폴리곤 하나를 1분 이내에 그려 완성할 수 있다.
- **SC-002**: 사용자는 폴리곤 2개를 선택한 뒤 3초 이내에 합치기 연산 4종(union/intersection/xor/difference)
  중 원하는 결과를 확인할 수 있다.
- **SC-003**: 사용자는 폴리곤 1개를 분할선으로 나눠 2개의 독립된 폴리곤으로 만들 수 있다.
- **SC-004**: 데모를 처음 보는 사용자가 버튼 라벨만 보고 그리기/선택/합치기/분할 기능을 90% 이상 정확히
  구분할 수 있다.

## Assumptions

- 이 기능은 데모 성격이며, 폴리곤 데이터의 서버 저장/영속화는 범위 밖이다 — 새로고침 시 폴리곤 상태는
  초기화되는 것을 기본으로 한다(프로젝트 전체가 FE 전용, 백엔드 없음 — CLAUDE.md "프로젝트 목적/현재
  범위" 참고).
- 지도 2개는 동일한 기능(그리기/선택/합치기/분할)을 각각 독립적으로 제공하는 두 개의 작업 공간이며,
  두 지도 사이의 데이터 동기화나 비교 기능은 이번 범위에 포함하지 않는다.
- 원본 코드(`dos/src/components/tms/delivery/Region/DeliveryRegionSettingTestManageBoard.jsx`)는 참고만
  하고 그대로 가져오지 않으며, UI/인터랙션 세부사항은 이 스펙 기준으로 새로 설계한다.
- 카카오맵 API 키는 `PUBLIC_KAKAO_MAP_API_KEY` 환경변수로 이미 로컬(`.env.local`)에 설정되어 있다.
- 로그인/인증, 다른 사용자와의 동시 편집(협업)은 범위 밖이다.
