# Quickstart: 폴리곤 제어 데모 화면 검증

구현 완료 후 아래 절차로 spec.md의 User Story/Acceptance Scenario를 수동으로 검증한다.

## 사전 준비

```bash
pnpm install
cp .env.example .env.local   # 이미 있다면 생략, PUBLIC_KAKAO_MAP_API_KEY 값 확인
pnpm dev
```

브라우저에서 `/polygon` 라우트로 이동한다.

## 검증 시나리오

### US1 — 폴리곤 그리기 (P1)

1. 좌측 지도에서 "그리기" 버튼을 누른다.
2. 지도 위 세 지점 이상을 클릭한 뒤 더블클릭으로 완료한다.
3. **기대 결과**: 클릭한 지점들을 꼭짓점으로 하는 폴리곤이 지도에 표시된다 (spec.md US1 시나리오 1).
4. 점을 2개만 찍고 완료를 시도한다 → 폴리곤이 생성되지 않아야 한다 (시나리오 2).

### US2 — 폴리곤 선택 (P2)

1. US1을 반복해 폴리곤을 2개 이상 만든다.
2. 폴리곤 하나를 클릭한다 → 선택 스타일(강조 색상 등)로 바뀌는지 확인한다.
3. 같은 폴리곤을 다시 클릭한다 → 선택이 해제되는지 확인한다.

### US3 — 합치기 연산 (P2)

1. 서로 겹치는 폴리곤 2개를 선택한다.
2. "union" 버튼을 누른다 → 두 폴리곤이 사라지고 합쳐진 영역의 새 폴리곤이 나타나는지 확인한다.
3. 같은 방식으로 "intersection" 버튼을 눌러 겹치는 영역만 남는지 확인한다.
4. 폴리곤을 1개만 선택한 상태에서 연산 버튼을 누른다 → "2개 이상 선택 필요" 안내가 뜨는지 확인한다.

### US4 — 폴리곤 분할 (P3)

1. 폴리곤 1개를 선택하고 "분할" 도구로 폴리곤을 가로지르는 선을 그린다.
2. 원래 폴리곤이 사라지고 선 양쪽의 폴리곤 2개가 새로 표시되는지 확인한다.
3. 폴리곤을 가로지르지 않는 선을 그려본다 → 분할이 실행되지 않고 오류 안내가 뜨는지 확인한다.

### 환경변수 누락 시나리오 (FR-011)

1. `.env.local`의 `PUBLIC_KAKAO_MAP_API_KEY`를 비운 채 `pnpm dev`를 재시작한다.
2. `/polygon` 라우트 진입 시 지도 대신 안내 메시지가 표시되는지 확인한다.

## 자동 테스트

```bash
pnpm test   # polygonOperations.ts / polygonSplit.ts 단위 테스트 (TDD 대상)
pnpm lint
pnpm build
```

위 세 User Story별 수동 시나리오는 자동 테스트로 대체하지 않는다 — 카카오맵 SDK 의존 인터랙션은
ARCHITECTURE.md "외부 SDK 모킹 전략"에 따라 최소 모킹된 컴포넌트 테스트로만 보조 검증한다.
