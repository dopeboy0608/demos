## 결정 로그

- 패딩 제거 범위: `region-view`의 `margin: -24px` 네거티브 마진 패턴을 그대로 재사용해 `AppLayout` Content 패딩까지 상쇄. 로고/Gnb/Util/Recruit 등 고정 UI는 `xmark-stage` 내부 모서리 배치 그대로 유지.
- 리스트 모드: 완전 삭제(비활성화가 아님) — `XmarkStyleTabs`/`XmarkPortfolioList`/`XmarkListRow`/`getListMaxScroll` 등 전체 제거.
- 카드 수: `XMARK_GALLERY_PAGE_SIZE` 12 → 10.
- 최소 카드 크기: 사용자가 구체적 수치를 지정하지 않고 "합리적 기본값으로 진행"을 선택 → 01 구현 시 임의로 정하고 화면으로 검증받음. 그 이하 해상도에서는 브라우저 뷰포트 스크롤을 허용(페이지 자체 스크롤이 아님).
- 마우스 3D 패럴럭스 세부 수치(최대 회전각 등): 사용자가 "임의로 적당히 정해서 진행"을 선택 → 03 구현 시 정하고 화면으로 검증받음.
- PoC 재사용: 기존 `/xmark-poc`(`XmarkGalleryEntrancePoc`)를 03(마우스 3D 패럴럭스) 프로토타이핑에 활용하기로 결정. PoC 라우트 정리(삭제/유지)는 03 종료 시 결정.
- 휠 방향: 기존 "휠업=다음 페이지 / 휠다운=이전 페이지" 자체는 유지. 등장/퇴장 방향(위/아래)만 신규 요구사항대로 변경.

## 발견 사항 (③ 스펙-코드 불일치, 스토리 본문은 건드리지 않음)

- 이슈 본문은 마우스 3D 회전에 대해 "원본 코드 참고"라 적었지만, 실제 코드(`src/features/xmark/`)에는 마우스 추적(`mousemove`/`pointermove`) 기반 회전 로직이 전혀 없음 — GSAP 타임라인 기반의 고정된(클릭/라이프사이클 트리거) 회전만 존재. 03에서 새로 설계 필요.
- `XmarkGalleryGrid.tsx:72-95`의 기존 진입(enter) 애니메이션은 이미 `y: ENTER_START_Y → 0` 수직 이동을 포함하고 있음. 그러나 이슈 작성자는 "현재는 제자리에서 회전임"으로 기억 — 실제 `ENTER_START_Y` 오프셋이 뷰포트 아래 기준이 아닐 가능성이 있어, 02에서 가치를 재검토하고 "뷰포트 아래에서 시작"으로 명확히 재조정함.
