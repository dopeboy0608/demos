## 결정 로그

- **데이터 소스**: 공공데이터포털 "국토교통부_(센서스경계)행정동경계"
  (https://www.data.go.kr/data/15125055/fileData.do, SHP, 공공누리 4유형). `cubensys/Korea_District`
  (GitHub)는 라이선스 미명시로 배제.
- **구 경계 도출 방식**: 별도 데이터셋 없이 행정동을 구 코드별로 union해서 도출 — "합치면
  상위 영역과 정확히 일치" 불변식(#47/#51)이 자동으로 성립하는 장점.
- **지번(세분류) 처리**: 공공데이터/SGIS 모두 무료 지번 폴리곤이 없어, 기존
  `splitAreaIntoPieces`(#51)로 동 영역 안을 n개 그룹으로 나눠 시뮬레이션(실제 지번 모양
  아님을 명시).
- **코드/이름 체계**: 서울 25개 구-센터는 실제 이름 사용(종로구, 청운효자동 등). 기존
  21개 절차적 센터는 기존 번호 체계(A01 등) 유지.
- **레이아웃 공존**: 서울 25개 구는 실제 좌표에, 기존 21개 절차적 센터는 격자 배치(#51)
  유지하되 기준점을 서울 바깥으로 이동해 겹치지 않게 함.
- **범위**: 이번 이슈에서 구 단위 센터 분리 + 동=소분류 + 지번그룹=세분류까지 한 번에
  진행(사용자가 단계 분리 없이 전체 진행 확정).
- Cross-check gate: 디자인 파일 없음(n/a), 코드 교차검증 결과 블로킹 항목 없음(이슈에
  인용된 현재 코드 구조는 이번 세션에서 직접 작성/확인), 다른 활성 브랜치와 `region-view`
  파일 충돌 없음(과거 머지된 브랜치만 존재) → 게이트 통과.

### 01. 서울시 행정동/구 경계 데이터 준비

- 공식 소스(공공데이터포털/VWorld)를 먼저 시도했으나 각각 캡차·로그인·GIS 도구 부재로
  막혀, 사용자 승인을 받아 `cubensys/Korea_District`(GitHub, 라이선스 미명시 — 비상업
  개인 데모 한정)의 WGS84 GeoJSON으로 전환(상세는 이슈 #64 "데이터 소스" 섹션 참고).
- `scripts/data/prepare-seoul-boundaries.py`(Python + shapely, 1회성, 프로젝트 의존성에는
  미포함): 행정동 424개를 `adm_nm`에서 구 이름을 파싱해 그룹화 → `unary_union`으로 구
  25개를 깨끗한 단일 Polygon으로 병합(슬리버 없음) → 좌표 소수점 6자리로 반올림.
  구현 중 `round_coords`가 shapely의 튜플 좌표를 리스트로만 체크해 반올림이 적용되지
  않는 버그를 발견해 수정(재실행 후 기존 결과와 완전히 동일함을 diff로 확인).
- `src/features/region-view/data/seoulDistricts.json`(127KB, 25개 구),
  `seoulDongs.json`(466KB, 424개 동)으로 저장.
- 확인: 구별 dongCount 합(424)이 전체 동 개수와 일치, 좌표가 WGS84 범위 내, 스크립트
  재실행 시 기존 산출물과 diff 없음(재현 가능성 확인).
- `pnpm lint` / `tsc --noEmit` / `pnpm test`(85개) 통과.
- 커밋: `6707c1c`.

### 02. 센터 데이터 모델 확장 및 격자 기준점 이동

- `constants.ts`: `RegionGroupProfile`에 선택적 `name`/`coordinates` 필드 추가. 기존 21개
  절차적 센터 배열을 `PROCEDURAL_PROFILES`로 이름 변경하고, `seoulDistricts.json`을
  `SEOUL_DISTRICT_PROFILES`(25개, 실제 이름/코드/좌표, `regionCount`=동 개수,
  `subRegionCount`는 임시로 동일값, `serviceType`은 인덱스 홀짝으로 DAWN/DAY 교대 배정)로
  변환해 `REGION_GROUP_PROFILES = [...PROCEDURAL_PROFILES, ...SEOUL_DISTRICT_PROFILES]`로
  합쳤다.
- 격자 기준점: 기존 `CITY_HALL`(서울시청) 대신 서울 밖(경북 인근) `PROCEDURAL_GRID_ANCHOR`를
  새로 둬, 서울 25개 구(실제 좌표)와 절차적 21개 센터(격자)가 겹치지 않게 했다. Node
  스크립트로 각 절차적 폴리곤의 최대 반경(진폭 1.36배)까지 포함해도 서울 bbox와 겹치지
  않음을 확인.
- `RegionViewSearchPanel.tsx`: 배송 센터 체크박스 라벨이 `option.code`를 그대로 보여주던
  버그를 발견해 `option.name ?? option.code`로 수정(서울 구는 "종로구" 같은 실제 이름,
  기존 센터는 그대로 코드 표시).
- 확인: 브라우저에서 서울 구 센터 선택/검색 시 크래시 없이 동작(지도 폴리곤 자체는 아직
  centroid 기반 절차적 육각형 — 실제 경계 렌더링은 03의 범위).
- `pnpm lint` / `tsc --noEmit` / `pnpm test`(85개) 통과.
- 커밋: `e37c5ad`.

### 03. 서울시 구-센터 소분류/세분류 지도 연동

- `regionViewApi.ts`의 `buildProfileDerived`를 분기: `profile.name && profile.coordinates`
  (서울 구)이면 새 `buildSeoulDistrictDerived`로, 그 외(절차적 21개)는 기존 로직 그대로
  처리한다.
- `buildSeoulDistrictDerived`: 소분류(regions)는 `seoulDongs.json`을 구 이름(guName)으로
  필터링한 실제 행정동 경계를 그대로 쓴다(regionCode=행정동코드 adm_cd, label=동 이름).
  세분류(subRegions)는 각 동 영역을 `splitAreaIntoPieces`(기존 `radialSubdivision.ts`)로
  동당 평균 3조각(`SIMULATED_PARCEL_GROUPS_PER_DONG`, `distributeCount`로 동별 실제 개수
  배정)으로 나눠 지번그룹을 시뮬레이션한다. `createAreaDivisions`에서 ring 생성 부분을
  분리한 `createAreaDivisionsFromRing`을 새로 export해 이미 있는(실제 경계) ring도 같은
  방식으로 분할할 수 있게 했다.
- MultiPolygon 동 처리: 데이터 조사 중 발견한 유일한 MultiPolygon 동(서교동, 마포구)은
  면적(shoelace)이 가장 큰 폴리곤만 분할하고, 나머지 작은 조각은 첫 세분류 조각에 그대로
  합쳐(`splitDongOuterRing`) 면적을 잃지 않게 했다.
- 라벨 처리: `RawDraftPolygon`/`RegionItem`/`SubRegionItem`에 선택적 `label` 필드를 추가해
  "code 대신 보여줄 실제 이름"을 따로 둠(코드 체계 자체는 adm_cd처럼 고유성이 필요해 그대로
  유지). `RegionViewMap.tsx`(지도 라벨)와 `RegionViewSubRegionResult.tsx`(좌측 목록)에서
  `label ?? code`로 표시해, 기존 절차적 센터(label 없음)는 그대로 코드가 보이고 서울 구는
  실제 이름이 보이도록 했다. 기본(센터) 레벨 폴리곤의 라벨도 `MOCK_POLYGONS`에서
  `profile.name`을 `label`로 채워 같은 방식으로 고쳤다(이전 소분류/세분류 하위 문제로 적어둔
  "맵 라벨이 코드로 보임" 갭을 여기서 해소).
- 확인: 브라우저에서 종로구/용산구/광진구 등 선택 후 검색 → 기본 레벨에 실제 구 경계와
  이름("종로구" 등) 표시, 줌인 시 소분류 레벨에 실제 동 경계와 이름("후암동") 표시, 더
  줌인 시 세분류 레벨에 "후암동-01"처럼 시뮬레이션된 지번그룹 라벨 표시를 모두 확인. 콘솔
  에러 없음(기존 antd Divider deprecation 경고만 존재).
- `pnpm lint` / `tsc --noEmit` / `pnpm test`(85개) 통과.
- 커밋: `20f1f66`.
